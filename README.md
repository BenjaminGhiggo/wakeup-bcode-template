# wakeup-bcode-template

Backend starter for **bolt.diy wake-up** ("BCode"): NestJS 12 on TypeScript 6 (strict), hexagonal bounded contexts, Drizzle ORM, PGlite / PostgreSQL, and an OpenAPI contract with an interactive Scalar client.

It runs inside StackBlitz WebContainer (Node 22.22.3, JS and WASM only, no native binaries) and on Node 24 LTS.

## Run

```bash
npm install
npm run dev     # nest start --watch (tsc builder, no native compiler)
npm run build   # nest build -> dist/
npm start       # node dist/main.js
```

| URL | What |
| --- | --- |
| `GET /api/health` | health check (all routes live under the `/api` prefix) |
| `/docs` | Scalar API reference and request client (send requests from the browser, no Postman needed) |
| `/openapi.json` | the OpenAPI 3 contract (a frontend generates its types and client from it) |

CORS is off: in production the frontend and the API share one origin behind the gateway.

## Layout (hexagonal, one folder per bounded context)

```
src/
  main.ts                  thin entry file (Nest needs one); delegates to platform/
  contexts/<ctx>/
    domain/                pure TypeScript: entities, value objects, errors, output ports (abstract classes)
    application/           use cases (plain classes, constructor injection, no decorators)
    infrastructure/        Drizzle schema + repositories, external adapters
    presentation/          controllers and DTOs: the only place with Nest/Swagger/class-validator decorators
  shared-kernel/           contracts shared between contexts (DomainError, integration events)
  platform/                composition root: modules that wire ports to adapters, database, OpenAPI, bootstrap
drizzle/                   SQL migrations generated by drizzle-kit (same files for PGlite and PostgreSQL)
```

Rules the wake-up gate G1 (dependency-cruiser) enforces:

- `domain/` imports only its own domain and `shared-kernel` (no NestJS, Drizzle, HTTP).
- `application/` never imports `infrastructure/` or `presentation/`.
- `presentation/` never imports `infrastructure/`; it receives use cases through Nest DI.
- Contexts never import each other.

`src/contexts/salud/` is a tiny example of every layer (a health use case backed by a database probe). Delete or replace it when you build real contexts; keep `src/platform/salud.module.ts` as the model for wiring.

The project is ESM (`"type": "module"`, `module: nodenext`): relative imports end in `.js`.

## Errors

Business rules throw a `DomainError` (`src/shared-kernel/domain-error.ts`). `DomainErrorFilter` (in `platform/`) returns it as a readable `400 { statusCode, error, message }`. Input shape errors come from `ValidationPipe` (class-validator) as 400 too.

## Database

`src/platform/database.provider.ts` chooses the driver from the environment. The Drizzle code is identical for all three.

| Environment | Driver |
| --- | --- |
| `DATABASE_URL` | PostgreSQL over TCP (`pg`, node-postgres) |
| `DATABASE_HTTP_URL` (+ `DATABASE_HTTP_TOKEN` as bearer) | PostgreSQL behind an HTTP bridge (Drizzle `pg-proxy`). The bridge receives `POST { sql, params, method }` and answers `{ rows }` |
| neither | PGlite (PostgreSQL in WASM), in memory; migrations from `drizzle/` run at startup, then the seeders in `src/platform/seed.ts` |

Define tables in `src/contexts/<ctx>/infrastructure/schema/*.schema.ts`, then `npm run db:generate` writes the SQL migration to `drizzle/`.

## Versions

Exact versions only (gate G3): `@nestjs/*` 12.2.0, `@nestjs/swagger` 12.0.2, `@scalar/nestjs-api-reference` 1.2.30, `drizzle-orm` 0.45.4, `drizzle-kit` 0.31.11, `pg` 8.23.1, `@electric-sql/pglite` 0.5.10, `typescript` 6.0.3 (Nest CLI 12 depends on `~6.0.2`). `engines.node` is `^22.22.3 || >=24.15.0`; `.nvmrc` is 24.
